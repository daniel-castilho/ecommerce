## Summary

Adds the storefront layer on top of the v0.20.0 FTS engine: search results now carry a
**pre-sanitized `ts_headline` snippet**, zero-hit searches show a distinct **empty state** with a
**Clear search** action, the sort dropdowns expose **human labels**, and the results list shows a
**result count** that reads correctly in the singular.

## What changed

| Story | Change |
|-------|--------|
| S1 Headline | `ProductSearchHit` DTO (`product` + `snippet`) surfaces through a new `searchWithSnippets` port method; the page query selects `ts_headline('english', coalesce(short_description, name, ''), <tsquery>, 'StartSel=<mark>, StopSel=</mark>, MaxWords=32, MinWords=12, MaxFragments=1')`. Fragments come from short description with a name fallback; headline is `NULL` (→ `null` snippet) for browser listing and for degenerate fallback passes (stopword/punctuation-only term, no usable lexemes) |
| S1 Sanitizer | `ProductRepositoryAdapter.sanitizeHeadline` escapes all HTML, then restores **only** `<mark>`/`</mark>`; the card renders `escape="false"` so highlights show but sourced markup can never arrive raw |
| S2 Empty state | `isSearchActive()` + `isSearchEmpty()` split the old catch-all message: "No products found" + **Clear search** button for zero hits on a query; "No products yet" for an empty catalog browse |
| S3 Sort labels | The dropdowns now render `Most relevant / Name / Price / Date added` and `Ascending / Descending` via `SelectItem`s; submitted values stay the enums. Default direction is descending |
| S4 Result count | `.search-summary` line above the grid: `"N products"` browsing, `"N products found"` searching, singular `"product"` |
| S5 Clear search | `clearSearch()` resets the term and page (keeps other filters) and refreshes; wired both in the summary and the empty state |

No schema change (headline runs over existing columns), no new dependency.

## Notes

- The headline tsquery shares the existing positional-bind machinery; because the fragment is
  emitted in the `SELECT` alias it consumes the **first** bind slot, so the page query binds in
  headline value → WHERE values → rank value order.
- Non-null snippets with no matching markup can still appear (e.g. the term matched only the name
  while the short description is non-null); the headline falls back to Postgres' first-fragment
  behavior. Root-cause follow-ups are listed as debt below.

## Lessons promoted

- **#45 (2026-08-14):** when you add a computed expression to the `SELECT` of a native query that
  already has strict positional-bind ordering (WHERE then ORDER BY), the new column's bind slot is
  allocated wherever its text appears — so the value list must be built in *textual* order, not
  grouped by clause. JPA binds `?N` by textual position; off-by-one here surfaced as
  `syntax error in tsquery: "%term%"` (ILIKE values leaking into `to_tsquery`) — caught only by
  the Testcontainers ITs.

## Explicit debt (not blocking)

- `ts_headline` falls back to an unmarked first fragment when the term matches only the name
  (short description non-null); a combined headline source is a candidate improvement
- Long-description weight C; `unaccent` / Portuguese config; `pg_trgm` did-you-mean
- `ts_headline` option tuning (highlight length balanced against card height)
