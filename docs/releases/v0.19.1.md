## Summary

The three admin report PDF exports now show a chart matching the on-screen one instead of
tables only: Revenue draws the daily/weekly/monthly series as bars, Product Performance
draws units-by-category as bars, and Customer Insights draws "New Customers by Date" as a
line. Charts are drawn with pure OpenPDF vector primitives on a `PdfTemplate` (crisp,
small files), reuse the exact series the UI computes (`ChartBar`/`ChartLine`), and use the
same design-token colors as the admin CSS (`--color-action-primary` bar fill, `--color-bg-subtle`
track, `--color-text-muted` labels). CSV export is unchanged.

## In scope (delivered)

- **`PdfChartDrawer`** (admin-dashboard `adapter/out/reporting`): one shared vector
  renderer with `drawBarChart` / `drawLineChart`, shared axis/label/title helpers, label
  truncation and a "No data" axis frame for empty series.
- **Payload DTOs**: `PdfChart` record added to `PdfDocument` between the KPI row and the
  tables; the three report beans pass the same `ChartBar` / `ChartLine` series the pages
  render (no re-query, no new aggregation).
- **Adapter**: `ReportGeneratorAdapter.generatePdf` embeds each chart
  (`Image.getInstance(template)`, scaled to the A4 content width) after the KPIs and before
  the data tables. RBAC, filename/`Content-Disposition` and CSV behavior unchanged.
- **Colors**: hardcoded hex of the admin design tokens used by the chart CSS, documented in
  `PdfChartDrawer` (no runtime CSS scraping).

## Out of scope / explicit debt

- No interactive/JS in PDF, no chart SaaS, no raster batching — purely vector.
- Perfect pixel-match with the CSS charts is not a goal; semantic parity (same series,
  labels, order) is.
- The Revenue table section keeps both the chart and its table rows (chart is added, table
  preserved).
