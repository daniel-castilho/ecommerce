## Summary

Completes the `order-checkout` epic (stories S1–S12): a full order state machine
(PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED, plus CANCELLED/REFUNDED),
checkout wizard with payment/shipping/notification mock adapters, idempotent checkout
by `requestId`, customer order history with cancel/refund, inventory reservation on the
catalog side (TTL + lazy expiry, race-safe against overselling), optimistic locking with
a friendly "please reload" message, and ArchUnit guard rails for the module. The catalog
storefront also gained primary-image cards, an optional admin image upload and a shared
design-system template + tokens rolled out to every page.

## Out of scope / explicit debt

- Real payment/shipping/notification providers (mock adapters only; see
  `docs/notification-system-guide.md`)
- Jakarta Security / real RBAC (manual session-role guard + `@RolesAllowed("ADMIN")`)
- Dedicated product-detail page (catalog cards link straight to checkout)
- Scheduled expiry job for inventory reservations (expiry is lazy: released on the next
  `reserve` of the same product)
- Pre-existing MyFaces NPE when the manage-product form submits an empty category selection
- External SQL writes to `tb_category`/roles need a server restart to clear app caches

## How to validate

```bash
mvn clean package -pl web -am
./scripts/run-liberty.sh
docker compose -f docker/docker-compose.yaml up -d localstack db
./scripts/bootstrap-localstack.sh
```

Smoke path:

1. Register a user → login; grant `ADMIN` in `admin/users.xhtml`.
2. Create/publish a product with image → it appears on `catalog.xhtml` with its image.
3. Click "Buy" → 4-step checkout (review → shipping PAC/SEDEX → payment → confirm) →
   order CONFIRMED, inventory reserved then confirmed, stock decremented.
4. Open "My orders" → order listed; cancel a CONFIRMED order (stock released back).
5. Refresh the confirmation page (PRG) — the same order is shown (idempotent by `requestId`).

## Lessons promoted

- #7 ArchUnit `ports_should_be_interfaces` counts nested records as non-interface classes —
  DTO records must live in `application/dto`, never nested in a port (hit twice in this
  release: `ReservationRequest`, `CheckoutCommand`/`ItemCheckoutRequest`); concurrent ITs
  need one `EntityManager` per worker thread + a `CyclicBarrier` inside a mocked port call
  to make the race deterministic; assert on DB row counts, not on mock call counts.
