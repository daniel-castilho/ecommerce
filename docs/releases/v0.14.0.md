## Summary

The wishlist module (domain/service/persistence, commit `f9e65d0` in the v0.13.0 window) now has
its **customer-facing UI**. The epic's last Must story is delivered, so the Wishlist epic is
complete.

1. **Product-detail toggle** — a logged-in customer sees an *Add to wishlist* / *Remove from
   wishlist* toggle in the product actions; guests see a *Log in to save* link and a *My Wishlist*
   link. The user id always comes from `SessionPort`, never from the form.
2. **`/web/wishlist/wishlist.xhtml`** — a login prompt for guests; for logged-in users the wishlist
   as a list (product image, name linking to the product detail by slug, price, *Added <date>*)
   with a per-item *Remove* button; an empty state with a *Browse the catalog* link.
3. **WishlistBean FacesMessage fix** — `h:messages globalOnly="true"` renders only the summary
   (`showDetail` defaults to `false`), so the user-facing text now lives in the summary, matching
   the `ProductReviewBean` convention on the same page ("Product added to your wishlist." /
   "Product removed from your wishlist.").

## In scope (delivered)

- wishlist: `WishlistBean` message text moved to the summary (add / remove / removeProduct /
  requireLogin); no domain or application changes.
- web: `product-catalog/product-detail.xhtml` gains the `wishlistForm` toggle (`rendered` on
  `loggedIn and productResolved`), the guest *Log in to save* link, and the *My Wishlist* link.
- web: new `wishlist/wishlist.xhtml` (login prompt, `wishlist-list`, per-item remove, empty state).
- web: `resources/css/base.css` wishlist block — consumes existing design tokens only (no new
  primitive/semantic/component token; design-system "rule of two" honoured).
- docs: `tasks/wishlist-backlog.md` marks S8 and the epic DoD done; README current state updated;
  CHANGELOG entry; lessons #25–#26.

## Out of scope / explicit debt

- **S10** (optional) catalog-card heart icon is still pending and is not part of the MVP.
- Wishlist items with no image render the name/price/date without an image (image is conditionally
  rendered), and product images in dev point at `http://localhost:4566` (LocalStack), which the
  browser blocks as mixed content over the local HTTPS page — a dev-environment note, not a defect.
- No cross-device wishlist sharing, quantities or "move to cart" — outside the MVP.

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Full build (final WAR):
mvn clean package -pl web -am

# Run (Open Liberty, https://localhost:9443/web/):
./scripts/run-liberty.sh
```

Smoke path (Open Liberty + Postgres, login `qa.admin@loja.com` / `SmokeTest@123`):

1. As a guest: product detail shows *Log in to save* and *My Wishlist*; `/wishlist/wishlist.xhtml`
   shows the login prompt.
2. Log in, open a product detail → the toggle reads *Add to wishlist*.
3. Click it → button flips to *Remove from wishlist* and the page shows "Product added to your
   wishlist.".
4. `/wishlist/wishlist.xhtml` lists the item with image, name, price and *Added <date>*.
5. Click *Remove* → the list is empty and the page shows "Product removed from your wishlist.".

## Lessons promoted

- #25 — `h:messages globalOnly="true"` renders the **summary** only (`showDetail` defaults to
  `false`); put the user-facing text in the summary, matching the page's existing message
  convention.
- #26 — `h:link` renders a context-relative `href` that already includes the app context path
  (`/web/...`); browser-QA scripts must build absolute URLs from that href without re-adding the
  context, otherwise you get `/web/web/...` 404s.
