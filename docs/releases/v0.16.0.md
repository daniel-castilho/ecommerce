## Summary

Replaces the view-scoped checkout lines with a **durable, per-user cart** persisted in Postgres
and integrated into place-order. Customers can add products from the product detail, review and
edit quantities on a dedicated cart page, and check out — the order is built from the persisted
cart, which is cleared only after a confirmed order. A server restart keeps the cart intact.

1. **Domain** — `Cart` / `CartLine` (one line per product, quantity ≥ 1), add / update / remove /
   clear / get use cases, `CartRepositoryPort` and `ProductLookupPort` (zero-framework domain).
2. **Application** — `CartApplicationService` (ACTIVE-product check, quantity upsert,
   optimistic-lock retry), `ProductLookupAdapter` (resolves live catalog data through
   product-catalog domain ports — no price is ever frozen in the cart), display DTOs
   `CartView` / `CartLineView`.
3. **Persistence** — `tb_cart` (unique `user_id`, `version` for optimistic locking, cascade
   lines) + `tb_cart_line` (migration **V24** + rollback); `CartRepositoryJpaAdapter` with
   in-transaction ops.
4. **UI** — `CartBean` (`@ViewScoped`), `/web/order-checkout/cart.xhtml` (quantities, update,
   remove, clear, subtotal, proceed-to-checkout), product-detail **Add to cart** button, cart
   link in the header.
5. **Checkout** — `CheckoutCommand` now carries the cart; `OrderApplicationService.checkout`
   reads the persisted cart, enforces active/stock/coupon rules as before, and clears the cart on
   success. The checkout wizard gains a step-1 **cart review** (live prices); confirmation page
   unchanged (PRG by `orderId`).

Also rolled into this release (committed since v0.15.0, previously untagged):

- **Coupons** — promotions module: coupon create/list UI, checkout discount quote and snapshot
  on the order (`tb_coupon` V22, `coupon_code`/`discount_amount` on `tb_order` V23).
- **Richer refund list filters** — `RefundSearchCriteria` (status, customer substring, date
  range, sort) with a dynamic `find()` on the repository port.
- **Repo hygiene** — report DTOs moved to `application/dto`, `ProductEditBean` logging,
  audit actor filter label, V5/V6 rollbacks.

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Cart + checkout ITs (Postgres 15 via Testcontainers):
mvn test -pl order-checkout -Dtest='CartRepositoryJpaAdapterIT,OrderApplicationServiceIT' -DfailIfNoTests=false

# Full build (final WAR):
mvn clean package -pl web -am

# Run (Open Liberty, https://localhost:9443/web/):
./scripts/run-liberty.sh
```

Smoke path (Open Liberty + Postgres, login `qa.admin@loja.com` / `SmokeTest@123`):

1. Product detail (`/web/product-catalog/product-detail.xhtml?slug=qa-test-widget`) → **Add to
   cart** → "Product added to your cart."
2. `/web/order-checkout/cart.xhtml` lists the line; edit quantity → Update → subtotal reflects it.
3. **Proceed to checkout** → step 1 shows the cart review → shipping → payment → **Place Order**.
4. Order-confirmed page shows the order; the cart is now empty.
5. Restart Liberty (`./scripts/run-liberty.sh`): the cart stays empty after the order — and a
   cart with items survives a restart before ordering.

## Lessons promoted

- #29 — JSF bindings: a typed `Map<String, Integer>` property does **not** coerce submitted
  values (Jakarta EL can't see the generic value type, so the raw `String` lands in the map and
  reading it into `Integer` throws `ClassCastException`); and `var="view"` in an `h:dataTable`
  collides with the reserved EL implicit object `view` (the `UIViewRoot`), failing at render.
  See `docs/lessons.md` for the golden rules.
