# Release v0.7.0 — Admin-dashboard monitoring & security lane (S25–S27): user admin, RBAC guard, ArchUnit

**Date:** 2026-08-03
**Git tag:** `v0.7.0`
**Baseline commit:** `73fb144` (tag `v0.6.0`)
**DoD met:** yes

---

## Summary

Closes the **admin-dashboard epic's monitoring & security lane**: S25 (admin user management,
right-sized), S26 (RBAC enforcement guaranteed by an automated coverage test) and S27 (ArchUnit
boundary tests for the admin-dashboard module). Admin features were already protected by
`web.xml` security-constraints + `@RolesAllowed("ADMIN")`; this release makes that protection
**testable and provable** — a new `AdminAccessControlCoverageTest` (web) fails the build if any
admin page is outside a protected url-pattern or any admin bean loses its `@RolesAllowed`.
A new `AdminDashboardHexagonalArchitectureTest` (7 ArchUnit rules) enforces the module's
hexagonal boundaries; writing the rules surfaced and fixed a real drift — the `DashboardSummary`
record nested inside the `DashboardMetricsUseCase` port interface moved to
`application/dto/DashboardSummaryDTO.java`.

## In scope (delivered)

- [x] **S25 — Admin user management (right-sized).** `AdminUsersBean` (`@ViewScoped`,
      `@RolesAllowed("ADMIN")`, user-account) at `/user-account/admin/users.xhtml`: user list
      with email/status/role filters, pagination (20/page), role assignment and block/unblock,
      backed by `ListUsersUseCase`/`AssignRoleUseCase`/`ChangeUserStatusUseCase`. Uses the
      existing `ADMIN` role as the gate — no `SUPER_ADMIN` role was introduced (see debt).
- [x] **S26 — RBAC enforcement guard (`AdminAccessControlCoverageTest`, web).** Source-scan test
      that locks in the RBAC contract: (a) every admin `.xhtml` (under `admin-dashboard/`,
      `user-account/admin/`, and `product-catalog/manageProduct.xhtml`) must be covered by a
      protected `web.xml` `<url-pattern>` — and no constraint may protect zero pages; (b) every
      admin bean source (`admin-dashboard` beans, `user-account` `Admin*` beans,
      `product-catalog` `ManageProductBean`) must carry `@Named` + `@RolesAllowed("ADMIN")`.
- [x] **S27 — ArchUnit admin boundary tests.** `AdminDashboardHexagonalArchitectureTest`
      (7 rules): domain ports are interfaces; domain has no `jakarta.*`/`javax.*` imports; no
      dependency on any top-level `..adapter..` class (own or other modules); application only
      consumes own + cross-module `domain`/`application` + `shared`; services implement input
      ports; beans live in `adapter.in.web`; DTOs are `final`.
- [x] **`DashboardSummaryDTO` refactor.** The `DashboardSummary` record was nested inside the
      `DashboardMetricsUseCase` port interface (a `ports_should_be_interfaces` violation — same
      trap as lessons #7). Moved to `application/dto/DashboardSummaryDTO.java`; port, service,
      bean and test updated.
- [x] Backlog: S25/S26/S27 marked done with acceptance-criteria status and implementation notes.

## Out of scope / explicit debt

- **Reporting lane S20–S23** (revenue/product/customer reports + PDF/CSV export) remains open —
  the only unfinished admin-dashboard stories.
- **No `SUPER_ADMIN` role / create-admin form.** S25 is right-sized: role assignment on the
  existing user list, gated by `ADMIN`. A super-admin tier, a dedicated create-admin form,
  per-user Edit/Delete actions, role badges and a last-login column are deferred.
- Unauthorized-access attempts are rejected (403 / login redirect) but produce **no audit-log
  entry** — the container 403 path is not wired to audit.
- Reporting (S20–S23) DoD items, refund list sorting/date-range filter, and `PaymentGatewayPort`
  real-provider integration remain open from previous milestones.

## How to validate

```bash
# Fast checks (no Testcontainers):
mvn -q -pl admin-dashboard -am test -Dtest=AdminDashboardHexagonalArchitectureTest -Dsurefire.failIfNoSpecifiedTests=false
mvn -q -pl web -am test -Dtest='AdminAccessControlCoverageTest,StatusBadgeCssCoverageTest' -Dsurefire.failIfNoSpecifiedTests=false

# Full build (final WAR):
mvn clean package -pl web -am
```

Smoke path (2026-08-03, Open Liberty + LocalStack + Postgres):

1. Login `qa.admin@loja.com` / `SmokeTest@123` → `catalog.xhtml`.
2. `GET /web/admin-dashboard/dashboard.xhtml` → KPIs render (unchanged from v0.6.0).
3. `GET /web/user-account/admin/users.xhtml` as ADMIN → list with filters; assign a role and
   block/unblock a user; verify the audit log records the action.
4. As a CUSTOMER user → `GET /web/admin-dashboard/dashboard.xhtml` and
   `/web/user-account/admin/users.xhtml` are rejected (403 / login redirect).
5. Run the S26/S27 tests above → green (the RBAC guard and ArchUnit rules pass).

## Lessons promoted

- #7 (extended) — the "nested record in a port violates `ports_should_be_interfaces`" trap hit a
  **third** module at S27 (`DashboardSummary` in `DashboardMetricsUseCase`). Golden rule holds
  module-wide: DTOs travel in `application/dto`, never nested in a port.
- #17 — guard cross-cutting web contracts (RBAC coverage, status-badge CSS) with source-scan
  tests living in the final WAR module, so both enforcement layers can't drift apart silently.
