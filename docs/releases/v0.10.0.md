## Summary

Full **Reviews & Ratings** module (`product-reviews`) implemented as a hexagonal module: customers
can submit a 1–5 star review (title + body, OWASP-sanitized) on the product-detail page, see the
average rating, star histogram and the paginated list of approved reviews, and a **verified purchase**
badge when the order-checkout shows a CONFIRMED/SHIPPED/DELIVERED order for that product. Admins
moderate the queue at `/admin-dashboard/reviews/` (list PENDING, approve, reject with reason). The
module depends only on `product-catalog`/`order-checkout` **ports**, has its own ArchUnit boundary
tests, and ships with Flyway migration `V17__product_reviews.sql`.

## In scope (delivered)

- Domain: `Review` aggregate (PENDING → APPROVED/REJECTED/HIDDEN state machine), `Rating` VO,
  `RatingAggregate`, exceptions (`DuplicateReviewException`, `InvalidRatingException`,
  `ReviewAlreadyModeratedException`, `ReviewNotFoundException`).
- Ports: 8 inbound use cases (submit, list approved, summary, get-by-id, list pending, approve,
  reject, hide own) + outbound `ReviewRepositoryPort`, `ProductLookupPort`, `OrderVerificationPort`.
- Thin integration adapters over `product-catalog`/`order-checkout` ports
  (`ProductLookupAdapter`, `OrderVerificationAdapter` — verified purchase only for
  CONFIRMED/SHIPPED/DELIVERED orders).
- Application: single `ReviewApplicationService`; DTOs in `application/dto`
  (`ReviewDTO`, `RatingSummaryDTO`, `ReviewListPage`, `SubmitReviewCommand`).
- Persistence: `ReviewJpaEntity` + `ReviewRepositoryAdapter`, unique `(author_id, product_id)` DB
  backstop, aggregate summary in one query, Flyway `V17__product_reviews.sql` +
  `docs/migrations/V17_rollback.sql`.
- Public UI: reviews section in `product-detail.xhtml` (stars, histogram via shared `barChart`
  composite, review cards, paginated list, "Log in to review" for anonymous, FacesMessages).
- Admin UI: `/admin-dashboard/reviews/list.xhtml` (PENDING queue, paginated) +
  `detail.xhtml` (approve / reject with mandatory reason), `@RolesAllowed("ADMIN")` + web.xml
  coverage (extended `AdminAccessControlCoverageTest`).
- Quality: `ReviewHexagonalArchitectureTest` (8 ArchUnit rules — surfaced and fixed nested
  `SubmitReviewCommand`/`RatingAggregate`), 85 module tests green (domain + service + beans + ITs).

## Out of scope / explicit debt

- Review images/media, helpfulness voting, vendor replies, AI moderation, incentives.
- Review editing/listing by the author in a UI (use cases exist, no customer-facing screen yet).
- Verified purchase is a **flag** (badge) — reviews are not blocked for non-purchasers.
- Moderation notifications to authors (`NotificationPort` deferred).
- Product rating on catalog cards / search (stays on the product-detail page).

## How to validate

```bash
# Fast check (no Testcontainers):
mvn -pl product-reviews test -Dtest='ReviewHexagonalArchitectureTest,ProductReviewBeanTest,ReviewModerationBeanTest,ReviewDetailBeanTest,ReviewApplicationServiceTest,ReviewTest,RatingTest' -DfailIfNoTests=false
mvn -pl web -am test -Dtest='AdminAccessControlCoverageTest,StatusBadgeCssCoverageTest' -Dsurefire.failIfNoSpecifiedTests=false -DfailIfNoTests=false

# Module ITs (Testcontainers Postgres):
mvn -pl product-reviews test -Dtest='*IT' -Dsurefire.failIfNoSpecifiedTests=false

# Full build (final WAR):
mvn clean package -pl web -am
```

Smoke path (Open Liberty + Postgres):

1. Login `qa.admin@loja.com` / `SmokeTest@123` (ADMIN+CUSTOMER).
2. `GET /web/product-catalog/product-detail.xhtml?slug=qa-test-widget` → "Customer reviews" section
   with stars, "No ratings yet", empty histogram, and the write-a-review form.
3. Submit a review (rating + title + body) → "Thanks for your review!"; a second submit for the
   same user+product is rejected as duplicate.
4. `GET /web/admin-dashboard/reviews/list.xhtml` → the review is PENDING; open it, Approve.
5. Reload the product page → the review now shows with the correct count and the histogram fills in.
