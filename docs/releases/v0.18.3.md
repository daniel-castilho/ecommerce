# Release v0.18.3 — Confirm modal no-JSF fallback submits via requestSubmit; logout form fix

**Date:** 2026-08-11
**Git tag:** `v0.18.3`
**Baseline commit:** `7d94774` (v0.18.2 — post-release QA fixes)
**DoD met:** yes (unit + ArchUnit suites green; resend smoke verified end-to-end in
Chromium: confirm triggers a real form POST and the row resets to PENDING)

---

## Summary

Two small web-layer fixes. First, the confirm modal's no-JSF fallback (`jsf` undefined,
pages without `faces.js`) used `el.click()`, which re-ran the target button's own
`lojaConfirm.show(...); return false;` handler and so never submitted the form — the
admin "Resend" action looked fine but silently did nothing. The fallback now calls
`form.requestSubmit(el)`, which fires the real submit (including the button's
`name/value`, so the JSF action resolves) without re-triggering the `return false`
onclick. Second, the profile page logout action now lives inside a proper `<h:form>`.

## In scope (delivered)

- **Confirm modal no-JSF fallback fixed** — `confirm-modal.xhtml` uses
  `el.form.requestSubmit(el)` when `jsf`/`jsf.ajax` is unavailable, falling back to
  `el.click()` only if `requestSubmit` is missing. Verified in a real browser: clicking
  Confirm sends `POST deliveriesForm:...:resendBtn=Resend` and the delivery row resets
  from EXHAUSTED/FAILED to PENDING with attempt 0.
- **Profile logout fixed** — the logout command button is now wrapped in `<h:form>`, so
  it posts the JSF form instead of issuing a bare GET that could be ignored.

## Out of scope / explicit debt

- No behavior change to dispatch/backoff/EXHAUSTED or to the JSF-ajax path
  (`jsf.ajax.request`) that pages with `faces.js` already used.
- The test harness (patchright shipped with the codegpt extension) disables inline
  scripts via CDP, which masked the Resend flow during QA; manual/real-browser testing
  is authoritative for the web layer.

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Full build + run:
mvn -pl web -am install -DskipTests
./scripts/run-liberty.sh   # https://localhost:9443/web/
```

Smoke path (real browser — the extension's patchright harness disables inline JS):

1. Admin dashboard → "Notification Deliveries" → pick a FAILED/EXHAUSTED row.
2. **Resend**: the confirm modal opens; click **Confirm**.
3. Verify the row resets to PENDING with attempt 0, then the poller re-tries it
   (FAILED again while `localhost:25` is refused) — the modal must not just close.
4. User account → Profile → **Logout**: session ends and you return to the login page.

## Lessons promoted

- `docs/lessons.md` #38: a confirm modal's fallback must submit the form
  (`form.requestSubmit(el)`) rather than re-clicking the guarded button — the guarded
  button's `onclick` returns `false`, so `el.click()` silently cancels the submit.
