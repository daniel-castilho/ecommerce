# Release v0.17.1 — Catalog FTS native-query parameter fix (EclipseLink)

**Date:** 2026-08-10
**Git tag:** `v0.17.1`
**Baseline commit:** `813220c` (v0.17.0 — guest cart S12 + FTS ranking)
**DoD met:** yes (FTS search 500 reproduced in the browser, fixed, and re-verified end-to-end;
product-catalog IT suite green, WAR builds, full storefront smoke green)

---

## Summary

Patch release fixing a **runtime-only defect** the v0.17.0 smoke exposed: the catalog text search
returned HTTP 500. The FTS native query used **named parameters**, which the WAR's JPA provider
**EclipseLink** does not bind inside native SQL — it passed the raw `:tsquery` / `:like` / `:status`
literals to PostgreSQL, aborting with `syntax error at or near ":"`. The Testcontainers adapter ITs
run under **Hibernate** (which binds named parameters), so the bug was invisible to the suite.

Fix: the FTS native query now uses **positional parameters** (`?N`), bound with
`setParameter(n, ...)` — supported identically by EclipseLink and Hibernate. Behavior unchanged
(`ts_rank` ranking, prefix `tsquery` + ILIKE fallback, RELEVANCE default sort).

## In scope (delivered)

- product-catalog: `ProductRepositoryAdapter.searchByText` / `ftsWhere` / `ftsOrderBy` rewritten to
  positional placeholders via a small `FtsBindSlots` counter; `setFtsParams` replaced by
  `bindPositional` + `ftsParamValues`. The count and page native queries share one value order so
  the ORDER-BY `ts_rank` slot lines up.
- docs: `docs/lessons.md` #30 — "Native SQL named parameters bind under Hibernate (ITs) but not
  EclipseLink (WAR runtime)" with the positional-parameter golden rule.

## Out of scope / explicit debt

- Same FTS semantics as v0.17.0 (indexed fields only, no long-description ranking).
- No DB migration — the fix is code-only.

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Adapter IT (Tests the FTS native path with positional params):
mvn -pl product-catalog -am test -Dtest='ProductRepositoryJpaAdapterIT' \
    -Dsurefire.failIfNoSpecifiedTests=false

# Full build (final WAR) + run:
mvn clean package -pl web -am
./scripts/run-liberty.sh
```

Smoke path (Open Liberty + Postgres): open `/web/product-catalog/catalog.xhtml` as a guest, type
a search term that has FTS tokens (e.g. `QA` with the QA seed data) and click **Search** — the
page lists matching products instead of a 500, the sort select defaults to **RELEVANCE**, and
unmatched products stay out of the results.
