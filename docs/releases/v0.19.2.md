## Summary

Transactional order notification emails are now sent as **`multipart/alternative`**:
`text/plain` + an inline-styled `text/html` variant with design-token colors and spacing. The HTML
body is snapshotted at **claim** time on the outbox row (`body_html`, Flyway V30) beside the
existing text snapshot, so the poller never re-renders from live order state and resend re-sends
the same stored snapshots. Pre-V30 rows keep `body_html` NULL and stay text-only (no new failure
path). Plain text content is unchanged.

## In scope (delivered)

- **`OrderNotificationMessageBuilder`**: each event now builds a `Draft(subject, body, htmlBody)`
  — one shared HTML layout (header strip, title, content block, footer) with the admin design-token
  hex values embedded inline; event-specific blocks (items table + total for confirmed/shipped,
  reason / amount / rejection detail for refunds). All user- and catalog-derived strings are
  HTML-escaped (`&`, `<`, `>`, `"`, `'`).
- **Domain**: `NotificationDelivery` carries a nullable `bodyHtml` (safe `create` overload retains
  the legacy text-only signature; `reconstitute` restores it).
- **Persistence**: `body_html TEXT NULL` column (V30 + rollback); `claim` inserts it and
  `findDue`/`findDeliveries`/`resend` round-trip it; rows with NULL are deliberately included in
  the dispatch queue but sent text-only.
- **Processor**: `compose(...)` builds `multipart/alternative` (`text/plain; charset=utf-8` first,
  then `text/html; charset=utf-8`) when an HTML snapshot exists, else `setText` plain fallback.
  FROM/session handling unchanged (v0.18.1 binding).
- **Adapter**: `enqueue` stores both bodies; idempotency, preference flag and non-blocking
  checkout are untouched.

## Out of scope / explicit debt

- Payment/shipping providers (still mocked), push/SMS, marketing digests, unsubscribe center.
- No template engine, no CSS-inliner dependency — string templates only.
- The admin delivery log does not display `body_html` (text preview remains); resend works on
  either body format.

## How to validate

```bash
# Fast gate (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Outbox IT (Testcontainers Postgres):
mvn -pl order-checkout test -Dtest='NotificationDeliveryLogRepositoryIT'

# Full build:
mvn clean package -pl web -am

# Run (Open Liberty, https://localhost:9443/web/):
./scripts/run-liberty.sh
```

Smoke path:

1. Place an order → `tb_notification_delivery_log` row has non-null `body` and `body_html`.
2. Inspect the dispatched MIME: `Content-Type: multipart/alternative` with `text/plain` and
   `text/html` parts; HTML uses inline styles and `Loja` header strip.
3. Open the HTML part in a browser: readable order-confirmed content with items and total.
4. Admin → notifications → Re-send a stuck row: the same stored snapshots are re-queued.
5. Stop SMTP → checkout still succeeds; delivery rows go FAILED → EXHAUSTED as before.

## Lessons promoted

- Mail `MimeMultipart` content must be examined after `msg.saveChanges()`: before saving,
  GetContent on an unsaved `MimeMessage` reports only `text/plain`/(sub)types collapse. On
  Liberty `Transport.send` saves internally, so the shipped message is correct. Added as a note
  under the existing mail lessons in `docs/lessons.md`.
