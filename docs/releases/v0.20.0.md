## Summary

Raises catalog text search from the V25 expression-GIN approach to a **reference PostgreSQL FTS
implementation**, entirely inside Postgres: a **STORED weighted `tsvector` column** behind a GIN
index, user queries parsed with **`websearch_to_tsquery`** (phrases, `OR`, `-`), results ranked
by **`ts_rank_cd(…, 32)`** cover density, and a documented **prefix + ILIKE fallback** that only
runs when the primary FTS pass returns nothing, so former LIKE fragment recall is not lost.

## What changed vs V25

| Aspect | V25 (before) | V31 (now) |
|--------|--------------|-----------|
| Vector | inline `to_tsvector(…)` over name/sku/short_description | STORED `search_vector` column: `setweight` **A** (name, sku) + **B** (short_description) |
| Index | expression GIN (`idx_tb_product_fts`) | GIN on the column (`idx_tb_product_search_vector`); V25 index dropped |
| Query parser | prefix AND `to_tsquery('token:* & …')` built in Java | raw input → `websearch_to_tsquery` (safe, phrase/OR/- aware) |
| Rank | `ts_rank` | `ts_rank_cd(search_vector, tsquery, 32)` cover density |
| Fallback | always-OR `ts_rank OR ILIKE` in one query | empty-FTS-hit → prefix tsquery OR ILIKE name/sku |

Long description is still **not** indexed: `description` is a `@Lob` column whose physical type
varies per environment (same reason as V25 — explicit debt), so the generated column stays
portable.

## Deployment notes

- Migration `flyway/sql/V31__product_fts_weighted_stored.sql` adds a `GENERATED ALWAYS …
  STORED` column (backfill on apply) and builds a GIN index; for very large catalogs this is a
  table rewrite — apply during a maintenance window. Rollback: `docs/migrations/V31_rollback.sql`
  (restores the V25 index, drops the column).
- FTS native SQL remains positional-only (`?N`) for EclipseLink; count and page queries share
  the same WHERE and bind order.

## Fallback policy (S3)

When the primary `search_vector @@ websearch_to_tsquery` pass returns **zero hits**, one fallback
pass runs: `search_vector @@ to_tsquery('token:* & token:*')` **OR** `name/sku ILIKE '%term%'`.
This preserves prefix recall ("smartp" → "Smartphone", via `to_tsquery` prefix) and interior
fragments ("uper" → "SuperWidget", via ILIKE). Terms with no usable lexemes (punctuation-only,
stopword-only) degenerate to the ILIKE branch only; SKU-like/digit tokens now match through the
indexed SKU (weight A) in the primary pass — no LIKE needed. Tests cover all of these and prove
no silent 500 on odd input (`!!!`, blanks, very long strings).

## Lessons promoted

- **#44 (2026-08-14):** a `GENERATED ALWAYS AS (…) STORED` `tsvector` cannot be declared by a JPA
  entity mapping, so the Testcontainers `drop-and-create` schema does not carry it. Apply the
  column + GIN in `AbstractIntegrationTest` right after the `EntityManagerFactory` is created and
  keep that DDL in sync with the Flyway migration (weights must match), or the FTS native SQL
  fails only at runtime.
