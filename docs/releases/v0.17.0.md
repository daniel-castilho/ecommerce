# Release v0.17.0 — Guest cart + merge on login (S12); catalog FTS ranking

**Date:** 2026-08-10
**Git tag:** `v0.17.0`
**Baseline commit:** `3459834` (v0.16.1 — catalog-card Add to cart S11)
**DoD met:** yes (cart epic S12 + FTS epic complete; full unit/ArchUnit suite green, WAR builds)

---

## Summary

Minor release with two independent features that close the outstanding post-v0.16.1 work:

1. **Guest cart (S12)** — anonymous shoppers can build a durable cart without logging in; it
   survives a server restart and folds into the user cart on login.
2. **Postgres full-text search ranking** — catalog text search now ranks matches via
   `to_tsvector` / `ts_rank` with a GIN expression index (V25), and **RELEVANCE** becomes the
   default catalog sort.

## In scope (delivered)

- order-checkout — guest cart (S12):
  - `GuestCartSession` stores a session-scoped UUID; `CartBean` keys the cart by the user id when
    logged in or the guest id otherwise, so guests add / view / edit / clear a **durable** cart.
  - The existing `tb_cart.user_id` column reuses the 36-char guest UUID — **no schema change**.
  - `GuestCartMergeObserver` folds the guest cart into the user cart on login (`Cart.merge` sums
    quantities per product) and deletes the guest cart.
  - Checkout still requires an account: the cart page shows **Log in to check out** for guests,
    and the catalog / product-detail **Add to cart** buttons are no longer gated on login.
  - `cart.xhtml` renders the cart for guests too (previously login-only).
  - New `MergeGuestCartUseCase` port + `CartApplicationService.mergeGuestCart`.
- product-catalog — Postgres FTS ranking:
  - `ProductRepositoryAdapter` runs a native `to_tsvector('english', name || sku ||
    short_description)` query ranked by `ts_rank`; the term matches a prefix **AND** `tsquery`
    (`smart:* & phon:*`) with an ILIKE fallback, so no former LIKE result is lost — FTS only
    re-orders.
  - `V25__product_fts.sql` creates the GIN expression index (rollback in
    `docs/migrations/V25_rollback.sql`); the long description is not indexed (LOB column type
    varies between environments).
  - New `ProductSortField.RELEVANCE`, now the catalog default sort.
- docs: `tasks/product-catalog-backlog.md` and `tasks/persistent-cart-backlog.md` mark the FTS
  epic and S12 shipped; README and CHANGELOG refreshed for v0.17.0.

## Out of scope / explicit debt

- No cross-device guest cart sync (session UUID) — a guest who switches browser / session loses
  the cart on re-login (it is merged only in the same session).
- Real payment, shipping and notification providers remain mocked.
- Long-description search remains excluded from FTS ranking (indexed fields only).

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Full build (final WAR):
mvn clean package -pl web -am

# Run (Open Liberty, https://localhost:9443/web/):
./scripts/run-liberty.sh

# LocalStack + Postgres (product images / FTS):
docker compose -f docker/docker-compose.yaml up -d localstack db
./scripts/bootstrap-localstack.sh
```

Smoke path (Open Liberty + Postgres):

1. As a guest, open the catalog → **Add to cart** on an active/in-stock card → the cart page
   lists the line with **Log in to check out**.
2. Restart Liberty → the guest cart still holds the line.
3. Got to **Log in** → the guest lines merge into the user cart (quantities summed) and the
   guest cart disappears.
4. Catalog search for `smart` → `Smartphone` ranks first under the default **RELEVANCE** sort;
   a non-indexed LIKE match still appears below.

## Lessons promoted

None new — the FTS index/expression coupling is called out in the V25 header (guarded like the
source-scan contracts of lesson #17), and the guest-cart merge keeps the fold into the existing
`Cart` aggregate. `docs/testing-playbook.md` drops "guest cart" from its Do-not list now that it
has a story + human OK.

## Rollback

```bash
git checkout v0.17.0
# or previous tag: git checkout v0.16.1
```

SQL rollback: `docs/migrations/V25_rollback.sql` drops the GIN index — search falls back to LIKE
ranking. The guest cart needs no destructive rollback (additive code; reverting restores the
login-only cart).
