## Summary

Final story of the admin-dashboard **reporting lane** (S20 revenue, S21 product performance, now S22):
the **Customer Insights Report** at `/admin-dashboard/reports/customers.xhtml`. An admin picks a date
range and gets five KPIs — Total Customers, New Customers (this period), Repeat Customer Rate (%),
Average LTV, Churn Rate (90+ days inactive) — plus a "New Customers by Date" line chart. Metrics are
split across the modules that own the data: order-checkout computes the order-based metrics
(repeat rate, LTV) and exposes the `CustomerInsightsReportUseCase`; user-account computes the
customer-based metrics (daily new-customer series, inactivity cutoff); admin-dashboard only composes
and renders. Ships with the S22 backlog marked done and a pre-existing UI bug fix (`rendered` on
plain HTML elements, see lesson #20).

## In scope (delivered)

- Domain/ports (order-checkout): `CustomerInsightsReport` + `CustomerGrowthPoint` records,
  `CustomerInsightsReportUseCase` (input port), new outbound queries
  `OrderRepositoryPort.repeatCustomerCount()` and `.totalCustomerRevenue()` (both exclude
  `CANCELLED`/`REFUNDED`; repeat = `GROUP BY userId HAVING COUNT > 1`).
- Domain/ports (user-account): `UserGrowthPoint` record,
  `UserRepositoryPort.userGrowthSeries(from, to)` (daily bucketing, `TreeMap`) and
  `.countInactiveSince(cutoff)` (never-logged-in churns when `createdAt < cutoff`, otherwise
  `lastLoginAt < cutoff`).
- Application (order-checkout): `CustomerInsightsReportService` — injects `OrderRepositoryPort` +
  `UserRepositoryPort` (cross-module dependency on user-account **ports**, already in the pom and
  allowed in `OrderHexagonalArchitectureTest`); churn cutoff = `now() − 90 days` (service constant,
  the domain has no last-activity concept).
- admin-dashboard: `CustomerInsightsReportBean` (`@Named("customerInsightsReportBean")`,
  `@ViewScoped`, `@RolesAllowed("ADMIN")`; `generate()`, chart-lines/polyline helpers, pt-BR
  formatters) + `ChartLine` DTO (x/y percentages, label, title).
- web: `admin-dashboard/reports/customers.xhtml` (date-range form + KPI grid + inline SVG line chart
  with dots overlay + "Back to reports"), `reports/index.xhtml` card now links to the page, and
  `.line-chart*` CSS in `base.css` (design-system rule of two — no composite; existing tokens only).
- Bug fix (all three report pages): `rendered` on a plain `<div>` is a Facelets pass-through no-op,
  so the report cards rendered empty on a plain GET. Switched to
  `<h:panelGroup layout="block" styleClass="card" rendered="...">` (lesson #20).
- Quality: 5 service unit tests (metrics, zero-customers, null/reversed range, 90-day cutoff via
  `ArgumentCaptor`), 8 bean unit tests (incl. polyline math + single-point centering), 4 new
  order-checkout IT cases, 5 new user-account IT cases; full gate green
  (`mvn -pl admin-dashboard,web -am test`: 85 + 65 + 6 tests).

## Out of scope / explicit debt

- CSV/PDF export of reports (S23, needs human-approved dependencies).
- "Inactive for 90+ days" is derived from `lastLoginAt`/`createdAt` — the `User` model has no
  explicit last-activity/last-order timestamps yet.
- No per-customer drill-down (list of repeat customers, LTV breakdown) — aggregate metrics only.
- Line chart is a one-off inline SVG; a shared chart composite stays deferred until a second line
  chart appears (rule of two).

## How to validate

```bash

mvn -pl order-checkout -am test -Dtest='CustomerInsightsReportServiceTest,OrderHexagonalArchitectureTest' -DfailIfNoTests=false
mvn -pl admin-dashboard -am test -Dtest='CustomerInsightsReportBeanTest,AdminDashboardHexagonalArchitectureTest' -DfailIfNoTests=false

# Adapter ITs (Testcontainers Postgres 15):
mvn -pl user-account test -Dtest='UserRepositoryJpaAdapterIT'

# Full build (final WAR):
mvn clean package -pl web -am

# Run (Open Liberty): ./scripts/run-liberty.sh
```

## Lessons promoted

- #20 — `rendered` on a plain HTML element is a Facelets pass-through no-op: gate conditional
  content with `<h:panelGroup layout="block">` or `<ui:fragment>`, and hunt for a literal
  `rendered="..."` attribute in the served HTML when a "hidden" element still shows up.
