# Release v0.18.2 — Post-v0.18.1 QA fixes (admin resend + poller shutdown hygiene)

**Date:** 2026-08-11
**Git tag:** `v0.18.2`
**Baseline commit:** `9ba186a` (v0.18.1 — notification outbox hardening)
**DoD met:** yes (unit + ArchUnit suites green, `NotificationOutboxDispatcherTest`
covers the shutdown cancel, admin resend path smoke-visible in the delivery log page)

## Summary

Small QA-fix release closing the two defects the v0.18.1 smoke surfaced: the admin
"Resend" action on the notification delivery log did not actually re-queue the row
(and the confirm modal was 500-ing admin pages), and a hot redeploy leaked a zombie
outbox poller that kept failing against the destroyed Weld context every 5 s.

## In scope (delivered)

- **Admin resend fixed** — `list.xhtml` gives the resend button a stable `resendBtn`
  id and targets `this.id` in the confirm modal, so the modal resolves the row button
  and `DeliveryLogBean.resend` actually re-queues the delivery.
- **Confirm modal rewritten as a Facelets tag** — `confirm-modal.xhtml` was registered
  in `loja.taglib.xml` as a Facelets tag (`<tag><source>`) but implemented as a JSF
  composite (`cc:interface`/`cc:implementation`), which made admin pages 500. It now
  follows the tag protocol (`<ui:composition>` + plain EL attributes) and escapes `&&`
  as `&amp;&amp;` so the inline script parses as strict XML (lesson #22).
- **Outbox poller cancelled on shutdown** — `NotificationOutboxDispatcher` now cancels
  the fixed-delay `ScheduledFuture` on `@Destroyed(ApplicationScoped.class)`, so a hot
  redeploy/stop no longer leaves a second poller running against a destroyed CDI context
  and spamming `ContextNotActiveException` every 5 s. Covered by
  `NotificationOutboxDispatcherTest`.

## Out of scope / explicit debt

- No behavior change to the dispatch/backoff/EXHAUSTED model from v0.18.1.
- Payment and shipping providers remain mocked.

## How to validate

```bash
# Fast unit/ArchUnit (no Testcontainers):
mvn test -Dtest='*Test' -DfailIfNoTests=false

# Full build + run:
mvn -pl web -am install -DskipTests
./scripts/run-liberty.sh   # https://localhost:9443/web/
```

Smoke path:

1. Place an order (or insert a due PENDING/FAILED row), wait for the poller to mark it
   FAILED/EXHAUSTED (`localhost:25` refused).
2. Admin dashboard → "Notification Deliveries" → **Resend**: the confirm modal opens,
   Confirm clears it, and the row resets to PENDING with attempt 0 (verify in
   `tb_notification_delivery_log`), then the poller picks it up again.
3. Stop and re-deploy the app: `messages.log` no longer shows repeated
   `ContextNotActiveException` stack traces from a leftover poller after shutdown.

## Lessons promoted

- `docs/lessons.md` #36: a `@ApplicationScoped` observer-scheduled task must be cancelled
  on `@Destroyed`; hot redeploy otherwise leaks a second poller against a dead context.
- `docs/lessons.md` #37: a component registered as a Facelets tag (`<tag><source>`) must
  be implemented as a Facelets tag, not a JSF composite (`cc:interface`) — composite
  markup in a tag slot 500s the page.
