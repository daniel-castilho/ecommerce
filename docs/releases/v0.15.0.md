## Summary

Closes the **last remaining acceptance criterion** of the S24 audit log viewer: the actor column
now shows the **resolved admin name** instead of a raw id, and the **entity type/ID** (USER,
PRODUCT, REFUND, ADDRESS) appear as their own columns instead of being buried in free-text
details.

1. **Resolved admin-name actor column** — `AuditLogBean.actorDisplayName(...)` resolves the actor
   via `FindUserUseCase.findById(...)` → full name; falls back to the subject (self-service
   events) and then to the raw id when the account no longer exists.
2. **Entity type/ID as separate columns** — `user_audit_log` gains nullable `entity_type` /
   `entity_id` (migration **V21**); `AuditLogObserver` populates them per event (e.g.
   PRODUCT_ARCHIVED → PRODUCT + product id, REFUND_PROCESSED/REJECTED → REFUND + refund id).
3. **Actor fix for cross-entity events** — PRODUCT_ARCHIVED / REFUND_* previously stored the actor
   in the `user_id` column with `actor_id` left null; they now record the actor in both `user_id`
   (kept non-null for the DB constraint) and `actor_id`, so the Admin column resolves correctly.

## Lessons promoted

- #28 — An audit log's actor should always be resolved through a use-case port (`FindUserUseCase`
  → full name), never rendered from the raw id; record the affected entity as first-class
  `entity_type`/`entity_id` columns rather than embedding it in free-text details. When the
  subject column is `NOT NULL` but the event targets a non-user entity (product/refund), keep
  `user_id` populated (with the actor id as the existing fallback) and set `actor_id` explicitly
  so the actor column resolves correctly.
