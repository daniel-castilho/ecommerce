# Release v0.14.1 — Wishlist catalog-card heart icon (S10)

**Date:** 2026-08-07

**DoD met:** yes (wishlist epic S1–S10 complete; full unit/ArchUnit suite green, `mvn clean

Liberty + Postgres)

## Summary

Patch release closing the wishlist epic's last (optional) story: a **♥/♡ heart icon on every
catalog card**. Logged-in customers toggle a product on/off their wishlist straight from the
card; guests see a heart that links to the login page. Same `WishlistApplicationService` use
cases — no domain or application changes.

## In scope (delivered)

- web: `product-catalog/catalog.xhtml` gains a per-card `h:form` with a heart command button
  (filled `♥` "Remove from wishlist" / outline `♡` "Add to wishlist", mutually exclusive by
  `rendered`); guests get a `♡` link to `/user-account/login.xhtml`.
- wishlist: `WishlistBean` exposes `toggleFor(productId)` (add/remove for a specific product,
  FacesMessage in the summary) and `inWishlistFor(productId)` backed by the set of
  wishlisted product ids loaded with the list; no service changes.
- wishlist: method named `inWishlistFor` (not `isInWishlistFor`) so the EL method invocation
  `#{wishlistBean.inWishlistFor(product.id)}` resolves — an `is`-prefixed boolean with an
  argument is not found as a method by EL (`MethodNotFoundException` at render time).
- web: `resources/css/base.css` adds `.product-card-title-row` + `.wishlist-heart` styles
  consuming existing tokens only (filled state uses the semantic `--color-feedback-error`).
- wishlist: `WishlistBeanTest` +6 cases (19 total) covering toggleFor add/remove/guest/
  product-not-available and wishlist-set tracking; browser smoke 8/8 steps.
- docs: lesson #27 (EL method invocation needs the literal method name), backlog S10 done,
  README current state.

## Out of scope / explicit debt

- The heart reflects the wishlist state on the current page only (re-render after a toggle).
  No optimistic/AJAX update — consistent with the rest of the JSF storefront.
- Products images still point at `http://localhost:4566` (LocalStack) in dev, which the browser
  blocks as mixed content on the local HTTPS page.

```bash
# Run (Open Liberty, https://localhost:9443/web/):
./scripts/run-liberty.sh
```

Smoke path (Open Liberty + Postgres, login `qa.admin@loja.com` / `SmokeTest@123`):

1. As a guest: each catalog card shows a `♡` heart that links to the login page.
2. Log in, open the catalog → the card shows `♡` "Add to wishlist".
3. Click it → the heart fills (`♥` "Remove from wishlist") and the page shows "Product added to
   your wishlist."; the wishlist page lists the product; the heart stays filled after a reload.
4. Click the filled heart → back to `♡`, "Product removed from your wishlist.", wishlist empty.

## Lessons promoted

- #27 — EL method invocation needs the literal Java method name: `#{bean.foo(x)}` does not
  resolve an `isFoo(String)` method; name the method exactly as the EL call and keep
  `is`/`get` prefixes for no-arg getters only.
