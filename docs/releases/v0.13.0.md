# Release v0.13.0 — Order timeline, blocked-checkout guard, cost price & audit filters

**Date:** 2026-08-07
**Git tag:** `v0.13.0`
**Baseline commit:** `b8d391b` (v0.12.0 — report export S23)
**DoD met:** yes (all module unit/IT suites green, ArchUnit boundaries green, full WAR builds,
audit-log filters + tooltip and order-detail timeline smoke-verified in the browser on Open Liberty
+ Postgres)

---

## Summary

Four back-office / checkout improvements that close long-standing backlog debt:

1. **Blocked-checkout guard** — an account that was suspended or blocked can no longer place
   orders. `OrderApplicationService.createOrder` now resolves the customer and rejects inactive
   accounts with a domain `AccountSuspendedException`; `CheckoutBean` maps it to a friendly message.
2. **Order status timeline + payment snapshot** — admin order detail now shows the order's status
   history (seeded "Order placed", appended on every transition) and its payment transactions,
   composed by `GetOrderDetailsService` from the order aggregate, the new `order_status_history`
   table (V18) and the payment mock. Closes the order-timeline part of the S18/S19 debt.
3. **Product cost price + gross profit margin** — `cost_price` on `tb_product` (V19, nullable,
   admin-only, never exposed to the storefront). Admin product create/edit accepts it, the admin
   product list shows Cost Price and Profit Margin, and the product performance report gains a
   Profit Margin (%) column on both tables.
4. **Audit log filters + detail tooltip** — the S24 audit-log viewer debt is closed:
   `AuditLogSearchCriteria` (actor, event type, details keyword, from/to date) flows through a new
   `AuditLogQueryPort` / `ListAuditLogsUseCase` into a dynamic-WHERE `AuditLogJpaAdapter`; the event
   type dropdown is populated from `distinctEventTypes()`. Long details are truncated to 60 chars
   with a full-text `title` tooltip.

## In scope (delivered)

- order-checkout: `AccountSuspendedException`; `createOrder` validates the customer is active
  (`UserRepositoryPort`); `OrderTimelineEntry` record; `OrderJpaEntity` + `OrderApplicationService`
  seed the timeline on placement and append on `changeStatus`.
- order-checkout: `ProductSalesStatsService` facade exposing `ProductSalesStatsUseCase`
  (`salesByProductId`) for the admin product list, and profit-margin math in
  `ProductPerformanceReportService` (`(revenue − costPrice × unitsSold) / revenue × 100`).
- product-catalog: `costPrice` on `Product`, `CreateProductCommand` / `UpdateProductCommand`, JPA
  entity + mapper, and `ProductApplicationService`; admin create/edit beans (product-catalog +
  admin-dashboard) accept and display it.
- admin-dashboard: `GetOrderDetailsService` now returns the timeline + payment transactions
  (`OrderTimelineEntryDTO`, `PaymentTransactionDTO`) rendered on
  `admin-dashboard/order-detail.xhtml`; `OrderDetailsDTO` extended; 12 new `GetOrderDetailsServiceTest`
  cases.
- admin-dashboard + user-account (audit log): `AuditLogSearchCriteria` record; `AuditLogQueryPort`
  (`findAuditLogs(criteria, page, pageSize)` + `distinctEventTypes()`); `ListAuditLogsUseCase`;
  dynamic-WHERE `AuditLogJpaAdapter` (LIKE actor/details, exact event type, UTC day range, params
  bound on both count + select); `AuditLogBean` filters (actor, event type, details, from/to date),
  `displayDetails` truncation + tooltip, UTC dates; `audit-log/list.xhtml` filter form + dropdown +
  pagination. New `AuditLogBeanTest` (7) and 7 new `AuditLogJpaAdapterIT` cases.
- QA fixes surfaced by browser smoke (unit suites were green): MyFaces `f:convertDateTime` crash on
  `Instant` (bean exposes `LocalDateTime`), invalid XML named entities (`&mdash;`, `&nbsp;`) that
  broke the parse of five `.xhtml` pages, EL method-name mismatch on the tooltip, EDT-vs-UTC date
  filters, and a flaky wishlist IT (Postgres microsecond precision).
- DB: `V18__order_status_history.sql`, `V19__add_cost_price_to_product.sql` (registered manually in
  `flyway_schema_history`; V16–V20 also applied to the dev database in this cycle).
- Tooling: `scripts/run-liberty.sh` rebuilds the runtime with `mvn -pl web -am install` so a fresh
  `mvn clean` no longer leaves sibling jars missing from `~/.m2`.

## Out of scope / explicit debt

- Audit-log actor is still a resolved-by-ID column (not a display name) and entity type/ID stay
  embedded in the free-text Details; the "loads in < 1 s" acceptance criterion (indexes on
  `user_audit_log`) is not measured.
- `cost_price` is `NULL` until entered; products without it show no margin.
- Timeline covers status transitions only — no separate payment timeline rows in the table (the
  payment section is a snapshot).
- Real payment/shipping/notification providers remain mocked.
- The wishlist module (`V20`, module + tests) landed in this window as a separate commit
  `f9e65d0`; its customer-facing UI pages are deferred to a follow-up story.

```bash

mvn test -Dtest='*Test' -DfailIfNoTests=false
```

Smoke path (Open Liberty + Postgres, login `qa.admin@loja.com` / `SmokeTest@123`):

1. Blocked checkout: block a customer, attempt checkout with that account → friendly
   "account blocked" message, no order created.
2. Admin order detail → status timeline with "Order placed" plus each transition, and the payment
   section with the transaction snapshot.
3. Admin product list → Cost Price + Profit Margin columns; create/edit product shows a Cost Price

4. Admin product performance report → Profit Margin (%) column on top/bottom tables.
5. Admin audit log → filter by event type (dropdown populated from `distinctEventTypes`), actor ID,

## Lessons promoted

- #22 — Facelets is strict XML: valid HTML named entities (`&mdash;`, `&nbsp;`) abort the page
  parse; use the Unicode characters or numeric entities.
- #23 — PostgreSQL `TIMESTAMP` stores microseconds: asserting exact `Instant` equality in ITs is
  flaky; compare with a sub-microsecond `Duration` tolerance.
- #24 — A fresh Liberty runtime (`mvn clean`) needs sibling module jars installed
  (`mvn -pl web -am install`), and the first `liberty:create` feature download is silent under
  `-q` — it looks frozen but is working.
