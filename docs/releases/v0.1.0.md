# Release v0.1.0 — Catalog storefront + order checkout MVP + user account

**Date:** 2026-08-01
**Git tag:** `v0.1.0`
**Baseline commit:** `5a6e3ec`
**DoD met:** yes

---

## Summary

Baseline snapshot of the modular monolith: `user-account` reference module complete
(registration, login, password reset, address book, profile, admin role assignment),
`product-catalog` epic steps 1–9 green (hexagonal domain/ports/persistence, search +
pagination, category tree cache, S3 image storage via LocalStack, admin CRUD + publish,
public ACTIVE listing, ArchUnit hexagon rules) and `order-checkout` MVP (domain `Order`
with OPEN/CONFIRMED/CANCELLED, transactional `CheckoutService.checkout()` with atomic stock
decrement, JSF cart + checkout + confirmation pages with PRG). Bean Validation is wired into
the JSF adapter beans across modules; `domain/` and `application/` stay framework-free.

## In scope (delivered)

- [x] user-account: register, login, password reset (token, consumed-token rejected), address
      book (add/set default/remove), profile, ADMIN role assignment, audit + email observers
- [x] product-catalog: Product/Sku/Slug/Category domain, ports, JPA adapters + mappers,
      `search()` + pagination, `decrementStock` (concurrency-tested), category cache with
      invalidation, S3 image upload (LocalStack), 6 use cases, 103 green unit tests
- [x] order-checkout: `Order`/`OrderItem` domain, `CheckoutService` (`@Transactional`, atomic
      stock decrement + order save), `OrderRepositoryPort` (save/findById), JSF checkout +
      order-confirmed (PRG), 21 tests green
- [x] admin-dashboard: `DashboardMetricsService` composing the other modules (no business rules)
- [x] Bean Validation on JSF adapter beans (no `jakarta.validation` in domain/application;
      ArchUnit still green)
- [x] Flyway DDL V5–V10 applied on `shop_db` (Postgres 15)

## Out of scope / explicit debt

- Jakarta Security / real RBAC (deferred epic; manual session-role guard + `@RolesAllowed("ADMIN")`)
- Dedicated product-detail page (catalog cards link straight to checkout)
- Public catalog cards do not render product images yet
- Order lifecycle emails (no `OrderNotificationPort` yet — see `docs/notification-system-guide.md`)
- Pre-existing MyFaces NPE when the manage-product form submits an empty category selection
- External SQL writes to `tb_category`/roles need a server restart to clear app caches

## How to validate

```bash
mvn clean package -pl web -am
./scripts/run-liberty.sh
docker compose -f docker/docker-compose.yaml up -d localstack db
./scripts/bootstrap-localstack.sh
```

Smoke path:

1. Register a user → login; welcome email is best-effort (SMTP may be down).
2. Grant `ADMIN` in `admin/users.xhtml` → create/publish a product with image (object lands in
   the `product-images` bucket).
3. Open `catalog.xhtml` as guest → ACTIVE product listed with search/pagination.
4. Click "Buy" → cart pre-filled → checkout → order CONFIRMED, stock decremented atomically.
5. Reload the confirmation page (PRG) — the order is still shown.

## Lessons promoted

- #1 `@Version` must round-trip through the mapper for `@OneToMany` graphs (duplicate-INSERT trap).
- #3 close the `EntityManager` in IT `@AfterEach`; wrap adapter reads in `inTx(...)`; use
  `getResultList()` over `getResultStream()` for pagination.
- #4 pin docker-java `-Dapi.version=1.44` in surefire for Docker Desktop 29.2.1+.
- #5 identity-bearing value objects must get their id at creation (null id collapses all rows).
