## Summary

Fixes a **regression on the admin coupon list** (`/web/admin-dashboard/coupons/list.xhtml`):
opening the page with any coupon that had a validity window threw
`Cannot format given Object as a Date` (500) because `<f:convertDateTime>` cannot format
`java.time.Instant`. The list now formats the UTC window via
`CouponManagementBean.formatUtc(...)` and a new "Release regression smoke (browser)" section in
`docs/testing-playbook.md` documents the required pre-tag browser checks (with read-only SQL
proofs) so this class of UI regression is caught before tagging again.

## In scope (delivered)

- **Fix**: `CouponManagementBean.formatUtc(Instant)` (UTC `yyyy-MM-dd HH:mm`) + `coupons/list.xhtml`
  renders the window through it. New coupons round-trip exactly: enter `2026-08-15T12:00` UTC →
  listed `12:00`. Verified with a freshly created `PRODUCT`-scope coupon end to end.
- **Test**: `CouponManagementBeanTest` (2 tests: UTC format, null-safe).
- **Docs**: `docs/testing-playbook.md` — new "Release regression smoke" section with a 9-step
  required checklist, read-only SQL proofs, and optional spot-checks; README table row updated with
  a pointer.

## Out of scope / explicit debt

  playbook).
- Payment/shipping providers still mocked; no other admin page touched.

## Lessons promoted

- `f:convertDateTime` accepts `java.util.Date`/`Calendar`/`String` — **not** `java.time.Instant`.
  Surface `Instant` as a pre-formatted string from the bean instead. (Existing note in
  `docs/lessons.md` area; check for a time-format entry.)
